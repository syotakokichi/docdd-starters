# Agent Teams - エージェントチーム運用ルール

## 概要

Claude Code のエージェントチーム機能を活用し、複雑なタスクを並列処理で効率化する。

## 判断マトリクス

エージェントチームを使用するかどうかの判断基準:

| 条件 | 単独実行 | チーム実行 |
|------|---------|-----------|
| 単一ファイル変更 | ✅ | - |
| 単一ドメイン変更 | ✅ | - |
| 複数ドメインにまたがる変更 | - | ✅ |
| リサーチ + 実装が必要 | - | ✅ |
| 独立した複数タスク | - | ✅ |
| 依存関係のある連続タスク | ✅ | - |

## 10パターン

### 1. 並列リサーチ

複数の技術選定・調査を同時に実行。

```
Agent A: ライブラリAの調査
Agent B: ライブラリBの調査
→ 結果を比較して選定
```

### 2. 設計壁打ち

異なる視点からアーキテクチャを検討。

```
Agent A: パフォーマンス観点で設計レビュー
Agent B: セキュリティ観点で設計レビュー
→ 両方の観点を統合
```

### 3. フロント・バック並列実装

フロントエンドとバックエンドを同時に開発。

```
Agent A: API エンドポイント実装
Agent B: UI コンポーネント実装
→ 統合テスト
```

### 4. テスト並列実行

異なるテストスイートを同時に実行。

```
Agent A: バックエンドテスト
Agent B: フロントエンドテスト
→ 結果集約
```

### 5. コードレビュー並列

複数ファイルのレビューを同時実行。

```
Agent A: ビジネスロジックのレビュー
Agent B: テストコードのレビュー
→ 指摘事項を統合
```

### 6. ドキュメント並列更新

複数ドキュメントを同時に更新。

```
Agent A: API ドキュメント更新
Agent B: README 更新
→ 整合性チェック
```

### 7. マイグレーション並列

異なるモジュールのマイグレーションを同時実行。

```
Agent A: モジュールA のマイグレーション
Agent B: モジュールB のマイグレーション
→ 統合テスト
```

### 8. 影響範囲調査

変更の影響を複数の観点から同時に調査。

```
Agent A: 直接的な依存関係の調査
Agent B: テストへの影響調査
→ 影響範囲レポート
```

### 9. 品質ゲート並列検証（/verify コマンド）

実装完了後の品質チェックを並列実行。

```
Agent A: テスト実行 + カバレッジ確認
Agent B: コード品質 + 計画との整合性チェック
→ PR作成可否判定
```

### 10. Issue 分析・計画（/plan コマンド）

計画立案時のリサーチと分析を並列実行。

```
Agent A: 既存コードベースの調査
Agent B: 公式ドキュメント・ベストプラクティスの調査
→ 計画策定
```

## 3つの実行モード

| モード | ツール | 用途 |
|--------|--------|------|
| 単独セッション | - | 単一ファイル変更、シンプルなタスク |
| サブエージェント | Task tool | 結果を返すだけの調査・検索 |
| エージェントチーム | Agent Teams | メンバー間で議論・クロスチェックが必要 |

**使い分けの基準**: メンバーが「結果を返すだけ」ならサブエージェント、「議論してクロスチェック」が必要ならチーム。

## 検証テンプレート

### バックエンド検証（5ロール）

```
1. Schema検証者: モデル・スキーマの整合性
2. Service検証者: ビジネスロジックの正確性
3. API検証者: エンドポイント・レスポンスの妥当性
4. クロスチェッカー: 全体の整合性確認
5. テスト実行者: テスト実行と結果報告
```

### フロントエンド検証（4ロール）

```
1. Component検証者: コンポーネント構造・Props
2. データ取得検証者: API連携・状態管理
3. UI/UX検証者: アクセシビリティ・レスポンシブ
4. クロスチェッカー: 全体の整合性確認
```

## ルール

1. **独立性**: エージェント間で依存関係がないタスクのみ並列化
2. **統合**: 並列実行後は必ず結果を統合・検証
3. **コンフリクト回避**: 同一ファイルを複数エージェントが同時に編集しない
4. **進捗管理**: TodoWrite でタスク進捗を可視化
5. **タスクサイジング**: 実装系は5-6タスク/メンバー、調査系は2-3タスク/メンバー
6. **委任モード**: リーダーはコードに触れず、調整に専念

## アンチパターン

- 単一ファイルの変更にチームを使う（オーバーヘッドが大きい）
- 順序依存のあるタスクを並列化する（結果が不整合になる）
- 同一ファイルを複数メンバーが同時編集する（コンフリクト発生）
