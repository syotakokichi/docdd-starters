# 独立レビュー結果コメントテンプレート

`/review` 完了時に Issue コメントとして残すテンプレート。
`/verify` の事実確認とは別レイヤーで、**実装者文脈を外した見落とし検出** の結果を記録する。

> **記法ルール**: 後続で evidence-checker を導入する際の互換性を保つため、以下を厳守する:
> - **見出し**: `## 独立レビュー結果（/review）` をそのまま使う（`/verify` のサマリーと混同しない）
> - **5 軸**: バグ / 回帰リスク / 設計不整合 / テスト不足 / ドキュメント更新漏れ — 各軸を必ず記載（指摘なしなら「なし」）
> - **優先度**: P1（必須）/ P2（推奨）/ P3（参考）の 3 段階 — 装飾なし
> - **残留リスク**: 本セッション内で解消できなかった項目を必ず明記（なければ「なし」）

---

```markdown
## 独立レビュー結果（/review）

### Status
- [完了 / 継続 / ブロッカーあり] — 1 行で記載
- 次アクション: `/pr <N>`（PR 作成）/ 修正後に `/review` 再実行 / ユーザー判断待ち（理由）

### 実行コンテキスト
- セッション: [新規セッション / 継続セッション]（`/review` は **新規セッション推奨**）
- レビュアー: [Codex CLI 単独 / 手動 handoff]
- 実行コマンド: `codex review --base main` / 実行省略（理由）
- 入力固定: `git diff $(git merge-base HEAD origin/main)..HEAD` / Issue #<N> 本文 / `/verify` コメント

### 5 軸レビュー指摘

#### 1. バグ（ロジック誤り・null 漏れ・境界条件・例外処理）
| 優先度 | 指摘 | 対応 |
|:-----:|------|------|
| P1 | [指摘内容] | [修正済み / 対応中 / 却下（理由）] |
| P2 | [指摘内容] | [対応 / 非対応（理由）] |

> 指摘なしの場合は「なし」と記載

#### 2. 回帰リスク（既存機能への影響・後方互換性）
| 優先度 | 指摘 | 対応 |
|:-----:|------|------|
| P1 | [指摘内容] | [修正済み / 対応中 / 却下（理由）] |

#### 3. 設計不整合（レイヤー責務逸脱・抽象度のばらつき・命名）
| 優先度 | 指摘 | 対応 |
|:-----:|------|------|
| P2 | [指摘内容] | [対応 / 非対応（理由）] |

#### 4. テスト不足（追加テスト未追加・エッジケース未カバー）
| 優先度 | 指摘 | 対応 |
|:-----:|------|------|
| P1 | [指摘内容] | [修正済み / 対応中 / 却下（理由）] |

#### 5. ドキュメント更新漏れ（DocDD / API yaml / CLAUDE.md / README）
| 優先度 | 指摘 | 対応 |
|:-----:|------|------|
| P2 | [指摘内容] | [対応 / 非対応（理由）] |

### 集計
- P1 必須: X 件（解消 Y 件 / 未解消 Z 件）
- P2 推奨: X 件（解消 Y 件 / 非対応 Z 件）
- P3 参考: X 件（記録のみ）

### 残留リスク
[本セッション内で解消できなかった項目とその扱いを記載。なければ「なし」]

- [残留リスク 1: 影響範囲、理由、対応案]
- [残留リスク 2: 影響範囲、理由、対応案]

### 次アクション
- [P1 未解消があれば修正後に `/review` 再実行]
- [P2 採否を Issue 本文に転記]
- [問題なければ `/pr <N>` で PR 作成へ]
```
