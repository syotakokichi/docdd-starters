# Codex コードレビュー観点メモ

`codex review --base main` で差分レビューを実行する際の期待観点。

> **注意**: `codex review --base main` は `[PROMPT]` と同時使用できないため、
> このファイルはプロンプトとして直接投入するものではなく、
> Codex レビュー結果を評価する際の参考資料、および handoff 時の観点リストとして使用する。

---

## レビュー観点

### 1. 正確性

- ロジックにバグはないか（off-by-one、null チェック漏れ、型の不一致）
- エラーハンドリングは適切か（例外の握りつぶし、不適切な fallback）
- 境界条件は考慮されているか

### 2. セキュリティ

- SQL インジェクション、XSS、CSRF のリスクはないか
- 認証・認可のチェック漏れはないか
- 機密情報（APIキー、パスワード）がハードコードされていないか
- 入力バリデーションは十分か

### 3. パフォーマンス

- N+1 クエリは発生しないか
- 不要なデータの取得・計算はないか
- キャッシュ戦略は適切か

### 4. 設計

- 単一責任の原則に従っているか
- レイヤー間の依存方向は正しいか（presentation → service → infrastructure）
- 適切な抽象度か（過度な抽象化 / 抽象化不足）

### 5. テスト

- 新しいコードに対するテストが追加されているか
- テストは意味のあるアサーションを持っているか
- エッジケースがカバーされているか

### 6. 高リスク変更（該当する場合）

決済・認証・マイグレーション・契約変更・状態管理・外部リダイレクトに関わる変更は特に注意:

- データ整合性は保たれるか
- ロールバック手順は考慮されているか
- 既存データへの影響はないか

---

## 指摘の分類

| 分類 | 意味 |
|:----:|------|
| 🔴 必須 | バグ・脆弱性・データ損失リスク — マージ前に修正必須 |
| 🟡 推奨 | 設計改善・可読性・パフォーマンス — 判断して対応 |
| 🟢 参考 | スタイル・命名・ドキュメント — 記録のみ |
| ❌ 却下 | 誤検知・コンテキスト不足 — 却下理由を記録 |
