# Codex レビュー Handoff テンプレート

Codex CLI が未導入の環境で、手動レビューを依頼するためのテンプレートです。
以下の内容を Codex Web / ChatGPT / 別の LLM に貼り付けてレビューを依頼してください。

---

## 計画レビュー（`/2` Phase 5 の代替）

以下を貼り付けてください:

````markdown
# 実装計画レビュー依頼

以下の実装計画をレビューしてください。

## レビュー観点
1. バグ・脆弱性リスク: 計画通りに実装した場合に問題が生じる設計上の欠陥
2. スコープの妥当性: 過不足なく適切なスコープか
3. 技術的な実現可能性: 選択した技術・パターンの適切さ
4. 依存関係の見落とし: 影響範囲の漏れ
5. テスト計画の十分性: テストケースのカバレッジ

## 回答形式
- 日本語で回答
- 各指摘を 🔴必須 / 🟡推奨 / 🟢参考 で分類
- 指摘がなければ「指摘なし」と明記

## 計画テキスト

[ここに Issue 本文の計画セクションを貼り付け]
````

---

## コードレビュー（`/5` Step 7 の代替）

以下を貼り付けてください:

````markdown
# コード差分レビュー依頼

以下のコード差分をレビューしてください。

## レビュー観点
1. 正確性: バグ、off-by-one、null チェック漏れ、型の不一致
2. セキュリティ: インジェクション、認証漏れ、機密情報のハードコード
3. パフォーマンス: N+1 クエリ、不要な計算
4. 設計: 単一責任、レイヤー依存方向、適切な抽象度
5. テスト: 新コードへのテスト追加、エッジケースカバレッジ

## 回答形式
- 日本語で回答
- 各指摘を 🔴必須 / 🟡推奨 / 🟢参考 で分類
- 指摘がなければ「指摘なし」と明記

## コード差分

[ここに `git diff main` の出力を貼り付け]
````

## レビュー結果の記録

レビュー結果を受け取ったら、以下の形式で Issue コメントに記録してください:

```bash
gh issue comment <N> --body "## Codex レビュー結果（手動 handoff）

### 指摘一覧
- 🔴 [指摘内容]
- 🟡 [指摘内容]
- 🟢 [指摘内容]

### 対応
- 🔴 → [修正内容]
- 🟡 → [対応/非対応の判断理由]

---
*手動レビュー実施日: $(date +%Y-%m-%d)*"
```
