実装の品質検証を行い、PR作成前の品質ゲートを通過してください。

---

## 手順

### 1. 変更内容の確認

```bash
git diff main --stat
git diff main --name-only
```

### 2. テスト実行（変更箇所に応じて）

**バックエンドを変更した場合:**
```bash
make test-backend
```

**フロントエンドを変更した場合:**
```bash
cd apps/frontend && npm run lint:biome && npm run check:segments && npm run test:unit
```

**両方変更した場合:**
```bash
make test
```

### 3. 実装計画との照合

1. `gh issue view $ARGUMENTS` で計画を確認
2. 計画の各ステップが実装されているか検証
3. スコープ外の変更が含まれていないか確認

### 4. コード品質チェック

- [ ] 命名規則に準拠（`.claude/rules/file-naming.md`）
- [ ] テストが追加されている（新機能・バグ修正の場合）
- [ ] 既存テストが壊れていない
- [ ] 不要なデバッグコードが残っていない
- [ ] セキュリティ上の懸念がない

### 5. エージェントチーム検証（複雑な変更の場合）

複数ドメインにまたがる変更の場合、各領域の専門エージェントで並列検証：

```
- バックエンド変更 → backend-patterns スキルで検証
- フロントエンド変更 → frontend-patterns スキルで検証
- テスト追加 → testing-patterns スキルで検証
- ドキュメント更新 → docdd-workflow スキルで検証
```

### 6. 結果レポート

検証結果をユーザーに報告：

```markdown
## 検証結果

### テスト: ✅ / ❌
- バックエンド: [結果]
- フロントエンド: [結果]

### 計画との整合性: ✅ / ❌
- [差分があれば記述]

### コード品質: ✅ / ❌
- [指摘事項があれば記述]

### 総合判定: PR作成可 / 要修正
```

---

## 注意事項

- 全チェックがパスしたら `/6` でPR作成に進む
- 問題があれば修正後に再度 `/5` を実行
- 計画との大きな差分がある場合は Issue 本文を更新

## 関連コマンド

- `/4`: 実装
- `/6`: PR作成
- `/7`: マージ＆クリーンアップ

Remember to use the GitHub CLI (`gh`) for all GitHub-related tasks.
