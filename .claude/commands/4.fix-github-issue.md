GitHub Issue $ARGUMENTS の実装を行ってください。

**CLAUDE.md の開発フローに従って進めてください。**

---

## 手順

### Phase 1: 準備

1. `gh issue view $ARGUMENTS --comments` でIssueの内容を確認
   - `[実装計画]` がタイトルにあれば、計画に従って実装
   - なければ先に `/2 $ARGUMENTS` で計画を立てる

2. **Issue を「進行中」に設定**:
   ```bash
   gh issue edit $ARGUMENTS --remove-label "status:todo" --add-label "status:in-progress" 2>/dev/null || true
   ```

3. **適用スキルを読み込む**（Issueの内容に応じて選択）:

   | Issue involves... | Applicable Skill | Path |
   |-------------------|------------------|------|
   | Backend API / FastAPI | backend-patterns | `.claude/skills/backend-patterns/SKILL.md` |
   | Frontend / Next.js / UI | frontend-patterns | `.claude/skills/frontend-patterns/SKILL.md` |
   | Test implementation | testing-patterns | `.claude/skills/testing-patterns/SKILL.md` |
   | DocDD documents / 7-axis | docdd-workflow | `.claude/skills/docdd-workflow/SKILL.md` |

### Phase 2: 実装

1. コードベースを調査し、関連ファイルを特定
2. 計画に基づいて実装を進める
3. テストを書いて動作を検証

### Phase 3: 品質チェック（変更箇所に応じて実行）

実装完了後、**変更した箇所に応じて**品質チェックを実行：

**バックエンドを変更した場合:**
```bash
make test-backend
```

**フロントエンドを変更した場合:**
```bash
cd apps/frontend && npm run lint:biome && npm run check:segments && npm run test:unit
```

**両方変更した場合:**
```bash
make test
```

### Phase 4: 差分確認

計画との差分がある場合はIssue本文を更新：
- 当初計画と異なる実装になった場合
- 追加の決定事項が出た場合
- 予期しない問題が発生した場合

```bash
gh issue edit $ARGUMENTS --body-file /tmp/issue_update.md
```

## チェックリスト

実装完了前に確認：
- [ ] テストがパスしている
- [ ] 品質チェック（make test / npm run lint:biome && npm run check:segments && npm run test:unit）がパスしている
- [ ] 計画との差分があれば Issue を更新した
- [ ] コードがスキルのパターンに従っている

---

## 注意事項

- 計画（`[実装計画]`）がなければ先に `/2` を実行
- 品質チェックは変更箇所に応じて実行（全部やらなくてOK）
- 大きな変更があれば Issue本文を更新

Remember to use the GitHub CLI (`gh`) for all GitHub-related tasks.
