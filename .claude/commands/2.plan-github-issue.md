GitHub Issue $ARGUMENTS の実装計画を立案してください。

**時間をいくらかけてもいいので品質を優先してください。**
**リサーチして公式のベストプラクティスがあれば採用してください。**
**CLAUDE.md の開発フローに従って進めてください。**

---

**重要: このコマンドの最終ゴールは「Issue本文の更新」です。**
**Plan mode で計画を立てた場合も、ExitPlanMode を呼ぶ前に必ず `gh issue edit` でIssue本文を更新してください。**
**Issue更新なしで終了してはいけません。**

---

## 手順（段階的に進める）

### Phase 1: 理解

1. `gh issue view $ARGUMENTS --comments` でIssueの内容を確認
2. **適用スキルを読み込む**（Issueの内容に応じて選択）:

   | Issue involves... | Applicable Skill | Path |
   |-------------------|------------------|------|
   | Backend API / FastAPI | backend-patterns | `.claude/skills/backend-patterns/SKILL.md` |
   | Frontend / Next.js / UI | frontend-patterns | `.claude/skills/frontend-patterns/SKILL.md` |
   | Test implementation | testing-patterns | `.claude/skills/testing-patterns/SKILL.md` |
   | DocDD documents / 7-axis | docdd-workflow | `.claude/skills/docdd-workflow/SKILL.md` |

3. **品質ルール** `.claude/rules/planning-quality.md` を参照
4. コードベースを調査し、影響範囲を特定

### Phase 2: ユーザーと相談（必須）

**計画を確定する前に、必ずユーザーと方向性を相談してください。**

相談すべき内容：
- 実装アプローチの選択肢（複数ある場合）
- 技術的なトレードオフ
- 優先順位の確認
- 不明点の確認

```
例: 「Issue #XX について調査しました。
実装方針として A と B の選択肢があります。
A: [メリット/デメリット]
B: [メリット/デメリット]
どちらで進めますか？」
```

### Phase 3: リサーチ（必要時）

- 公式ドキュメントやベストプラクティスをリサーチ
- アーキテクチャ決定がある場合はADRセクションを準備
- 新機能の場合はDocDD 7軸トレーサビリティ文書計画を準備

### Phase 4: Issue更新（必須）

1. **`gh issue edit` でIssue本文に計画を追記**
2. **`gh issue edit --title` でタイトルに `[実装計画]` を追加**
3. ラベル付与（最低2つ）:
   - 優先度: `High` / `Medium` / `Low`
   - 内容: `バックエンド` / `フロントエンド` / `テスト` / `インフラ` / `ドキュメント` / `バグ`

---

## Issue本文の更新テンプレート

**元の内容（背景・目的・受け入れ条件）は残したまま**、以下を追記：

```markdown
---

## リサーチ結果
[調査した公式ドキュメント、ベストプラクティス、参考実装]

## 影響範囲
[変更対象ファイル、依存関係、副作用]

## 重要ポイント
[特に注意が必要な箇所]

## 実装タスク
- [ ] タスク1
- [ ] タスク2
- [ ] タスク3

## 参照スキル
- backend-patterns
- testing-patterns

## 完了条件
- [ ] 全テストがパス
- [ ] pre-commit チェックがパス
- [ ] レビュー承認

（ADRセクション - アーキテクチャ決定がある場合）
（DocDD 7軸セクション - 新機能の場合）
```

---

## タイトルの更新

```bash
gh issue edit $ARGUMENTS --title "[実装計画] 元のタイトル"
```

## 長い計画の場合

```bash
# 1. 一時ファイルに書き出し
cat > /tmp/issue_$ARGUMENTS.md << 'EOF'
[既存の内容 + 計画]
EOF

# 2. Issue更新
gh issue edit $ARGUMENTS --body-file /tmp/issue_$ARGUMENTS.md
```

---

## 注意事項

- **一気に進めず、Phase 2 でユーザーと相談すること**
- コメントではなく **Issue本文を編集** して計画を追記
- 元のIssue内容は残す
- スキルファイルのパターン・制約に従う

Remember to use the GitHub CLI (`gh`) for all GitHub-related tasks.
